# HWP to Word

[English](README.md) | 한국어

컴퓨터에 있는 `.hwp` 파일을 터미널 명령어로 **편집 가능한 Word 문서(`.docx`)**로
변환합니다. 변환한 텍스트와 표를 편집할 수 있으며, 원본 파일은 변경하지 않습니다.

한컴의 공개 문서 형식을 바탕으로 **직접 구현한 HWP 3·HWP 5 파서**를 사용합니다.
`pyhwp`에 의존하거나 실패 시 해당 파서로 전환하지 않습니다. HWP 5 파일 컨테이너를
읽는 `olefile`과 Word 파일을 만드는 `python-docx`는 계속 사용합니다.
새 HWP 3 파서는 Python 표준 라이브러리만 사용하며, 추가 의존성은 없습니다.
HWP 3는 규격을 바탕으로 만든 테스트 파일로 검증한 실험적 부분 지원입니다.

**현재는 실험 단계입니다.** 서식이나 페이지 구성이 원본과 달라질 수 있으니 공유하거나
제출하기 전에 결과를 확인하세요. HWPX는 아직 지원하지 않습니다. Windows 실행 경로는
구현하고 모의 테스트로 검증했지만, 실제 Windows 컴퓨터에서의 변환은 추가 검증이 필요합니다.
Word에 설치하는 추가 기능이 아니라 터미널에서 실행하는 도구입니다.

## 시작하기 전에

- macOS 또는 Linux를 사용하세요. Windows 지원은 실험 단계입니다.
- [Node.js](https://nodejs.org/en/download) 18 이상(`npx` 포함)과
    [Python](https://www.python.org/downloads/) 3.9 이상을 설치하세요.
- 보호 설정이 없는 신뢰할 수 있는 HWP 3 또는 HWP 5 파일을 준비하세요. 기본 입력
    한도는 50 MiB이며, HWP 5는 아래 옵션으로 더 큰 파일과 여러 구역을 지원합니다.
    HWP 3는 50 MiB 이하, 구역 하나라는 기존 제한을 유지합니다.
- 첫 실행 시 도구와 필요한 패키지를 다운로드할 인터넷 연결이 필요합니다.

터미널에서 설치된 버전을 확인할 수 있습니다.

```sh
node --version
python3 --version
```

## 파일 변환하기

HWP 파일이 있는 폴더에서 터미널을 열고 다음 명령어를 실행하세요.

```sh
npx hwp-to-word "문서.hwp" "변환결과.docx"
```

`문서.hwp`는 실제 파일명으로, `변환결과.docx`는 원하는 Word 파일명으로 바꾸세요.
파일명이나 경로에 공백이 있다면 따옴표로 감싸 주세요. 폴더를 이동하지 않고 전체 경로를
지정할 수도 있습니다.

```sh
npx hwp-to-word "$HOME/Downloads/내 문서.hwp" "$HOME/Downloads/내 문서.docx"
```

`npx`가 `hwp-to-word` 설치 여부를 물으면 승인하여 진행하세요.
첫 변환은 Python 실행 환경을 준비하므로 시간이 더 걸릴 수 있습니다.
필요한 Python 패키지는 자동으로 설치됩니다.

### 이 저장소의 최신 코드 실행하기

이 저장소에 구현된 자체 파서를 사용하려면 저장소의 최상위 폴더에서 로컬 CLI를
실행하세요.

```sh
node bin/hwp-to-word.mjs "문서.hwp" "변환결과.docx"
```

필요한 Python 패키지를 자동으로 준비하며, 아래에 안내된 옵션도 동일하게 사용할 수
있습니다. `npx hwp-to-word`는 npm에 배포된 패키지를 실행하므로 이 저장소의 최신
변경 사항이 아직 포함되지 않았을 수 있습니다.

## 결과 열고 확인하기

변환에 성공하면 지정한 위치에 두 파일이 생성됩니다.

| 파일 | 용도 |
| --- | --- |
| `변환결과.docx` | Microsoft Word 또는 DOCX를 지원하는 편집기에서 열어 사용합니다. |
| `변환결과.report.json` | 텍스트 편집기로 열어 변환 중 발생한 경고를 확인합니다. |

원본과 비교하며 본문, 표, 페이지 나누기, 한글 글꼴을 확인하세요.
원본 글꼴이 컴퓨터에 없으면 줄바꿈과 간격이 달라질 수 있습니다.
Word에서 글자 크기를 키웠다면 문단의 줄 간격도 조정해야 할 수 있습니다.

보고서는 파서가 읽은 텍스트와의 일치 여부, 표의 행·열 수, 구역 수와 페이지 설정,
이미지 개수 등을 확인합니다.
**원본의 모든 요소나 시각적 배치가 보존되었다는 뜻은 아닙니다.**
`visual_layout_verified: false`는 레이아웃을 자동으로 검증하지 않았다는 의미이며,
이 값만으로 변환에 실패했다고 판단하지 않아도 됩니다.

보고서의 `"parser": "native-hwp3"` 또는 `"parser": "native-hwp5"`는 사용한 파서를
나타냅니다. 두 버전 모두 `.hwp` 확장자를 쓰며, 파일 내부의 식별 정보로 구분합니다.

기존 Word 파일이나 보고서는 덮어쓰지 않습니다. 다시 변환할 때는
`변환결과-v2.docx`처럼 새로운 출력 파일명을 지정하세요.

## 필요한 경우에만 사용하는 옵션

### 더 큰 HWP 5 파일 변환하기

로컬 저장소에서 실행할 때 다음과 같이 처리 한도를 지정할 수 있습니다.

```sh
node bin/hwp-to-word.mjs "큰문서.hwp" "변환결과.docx" --max-input-mb 200 --max-stream-mb 128 --max-expanded-mb 512 --max-records 500000 --reader-timeout 300
```

| 옵션 | 기본값 | 적용 대상 |
| --- | --- | --- |
| `--max-input-mb` | 50 | 입력 파일 크기 |
| `--max-stream-mb` | 64 | HWP 5 개별 스트림의 저장·압축 해제 크기 |
| `--max-expanded-mb` | 128 | 이미지를 포함한 HWP 5 전체 스트림의 압축 해제 크기 |
| `--max-records` | 200000 | HWP 5 스트림별 레코드 수 |
| `--reader-timeout` | 60 | 파서 제한 시간(초) |

모든 값은 양의 정수이며, 크기 단위는 MiB(1,048,576바이트)입니다. 입력 한도를
높여도 다른 한도는 자동으로 바뀌지 않습니다. 오류 메시지에 표시된 한도를 확인하세요.
HWP 3의 내부 제한은 유지됩니다. 선택한 HWP 5 한도와 파서 제한 시간은 보고서에 기록됩니다.

CLI는 중간 XML과 추출한 이미지를 임시 파일에 저장하여 중간 문서의 base64 이미지 복사본을
줄입니다. 성공·실패 후 임시 이미지는 삭제하지만, Word 문서 구조와 최종 이미지 데이터는
여전히 메모리를 사용합니다.
큰 문서는 입력 크기보다 훨씬 많은 메모리가 필요할 수 있으며, 지정한 크기 이하인
모든 파일의 변환이나 정확한 레이아웃을 보장하지는 않습니다.

### HWP 5의 여러 구역

구역을 번호 순서대로 읽어 Word 구역으로 만들고 각 구역의 페이지 크기, 방향,
여백과 머리말·꼬리말 거리를 유지합니다. 두 번째 구역부터는 새 페이지에서 시작합니다.
홀수·짝수 페이지 시작과 구역 번호 설정은 아직 지원하지 않습니다.
페이지 설정이 없는 구역은 이전 Word 구역의 설정을 사용하며, 첫 구역은 Word 기본값을
사용합니다. 페이지 시작 추정 기능은 구역마다 초기화되고 모든 구역이 한 단일 때만
작동합니다. 보고서는 구역 수와 명시된 페이지 설정을 검증하며 페이지 배치 자체는 검증하지 않습니다.

### 링크와 머리말·꼬리말

HWP 5의 웹·이메일·FTP 하이퍼링크는 클릭 기능과 표시 문구 서식을 유지합니다.
한 문단 안에서 시작하고 끝나는 링크를 지원하며, 중첩 링크나 여러 문단에 걸친 링크는
오류로 처리합니다. 파일 링크, 문서 내부 책갈피 링크, 지원하지 않는 주소는 표시 문구만
유지하고 경고합니다.

각 구역의 첫 문단에 정의된 머리말·꼬리말에서 텍스트, 서식, 표, 지원 이미지와 링크를
변환합니다. 홀수·짝수 페이지를 따로 지정하거나 양쪽에 적용할 수 있습니다. 다음 구역은
새 정의가 없으면 이전 구역을 이어받고, 명시적인 빈 정의는 이전 내용을 지웁니다.
동일한 페이지 유형의 반복 정의, 구역 중간의 내용 있는 정의, 첫 페이지 숨기기와 자동
쪽 번호 필드는 아직 지원하지 않습니다. 빈 머리말·꼬리말만 있는 기존 문서는 계속 변환합니다.
보고서는 내용, 구역 간 연결, 링크 주소를 검증합니다.

기존 텍스트 개수와 해시는 본문 기준이며, 머리말·꼬리말 텍스트는 별도로 집계합니다.
표·그림·링크 개수에는 명시적으로 작성한 머리말·꼬리말도 포함하며, 홀수·짝수 영역에
각각 작성한 정의는 각 영역에서 한 번씩 집계합니다.

### 원본의 페이지 시작 위치 유지하기

다단 편집이 아닌 HWP 5의 1단 문서라면 다음 옵션을 사용해 보세요.

```sh
npx hwp-to-word "문서.hwp" "페이지유지.docx" --preserve-source-pages
```

HWP에 저장된 줄 위치를 바탕으로 페이지 시작 지점을 추정합니다.
줄바꿈이나 전체 페이지 구성이 원본과 똑같아지는 것은 아니며, 다단 문서에는 사용할 수 없습니다.
HWP 3에서는 이 옵션에 경고를 남기고 페이지 나누기를 추정하지 않습니다.
문단에 명시된 페이지 나누기는 옵션 없이도 유지합니다.

### 없는 글꼴을 다른 글꼴로 바꾸기

원본 글꼴 이름과 컴퓨터에 설치된 대체 글꼴 이름을 연결하는 `font-map.json` 파일을
준비하세요. 예를 들어 나눔고딕이 설치되어 있다면 다음과 같이 지정할 수 있습니다.

```json
{
    "맑은 고딕": "Nanum Gothic"
}
```

```sh
npx hwp-to-word "문서.hwp" "글꼴변경.docx" --font-map "font-map.json"
```

글꼴을 설치하는 기능은 아닙니다. 대체 내역은 보고서에 기록되며, 글꼴 변경으로 배치가
달라질 수 있습니다. 이 옵션을 사용하지 않으면 원본 글꼴 이름을 유지합니다.

### 잘못된 텍스트 인코딩 복구하기

잘못된 UTF-16 인코딩 때문에 HWP 5 파일을 읽지 못하는 경우에만 다음 옵션을 시도할 수 있습니다.

```sh
npx hwp-to-word "문서.hwp" "텍스트복구.docx" --recover-text
```

**일부 문자가 바뀔 수 있습니다.** 잘못된 바이트 시퀀스를 대체 문자(U+FFFD)로 바꿉니다.
보고서의 `text_replacements` 항목을 확인하고 Word에서 해당 내용을 수정하세요.
모든 변환 오류를 해결하는 옵션도, 원본을 손실 없이 복구하는 기능도 아닙니다.
HWP 3는 별도의 문자 인코딩을 사용하므로, 이 옵션으로 미지원 문자 코드를 대체하거나
복구하지 않습니다.

## 문제가 생겼을 때

| 문제 | 해결 방법 |
| --- | --- |
| `npx: command not found` | Node.js를 설치한 뒤 터미널을 다시 여세요. |
| `Python 3.9+ is required` | Python 3.9 이상을 설치하세요. 별도 경로에 설치했다면 `HWP_TO_WORD_PYTHON`에 실행 파일 경로를 지정하세요. |
| Python 가상 환경 생성 실패 | Python에 `venv` 기능이 있는지 확인하세요. 일부 Linux 배포판에서는 별도 패키지 설치가 필요합니다. |
| 의존성 설치 실패 | 인터넷 연결과 프록시 제한을 확인한 뒤 다시 실행하세요. |
| 파일을 찾을 수 없음 | 경로와 확장자를 확인하고, 공백이 있는 경로는 따옴표로 감싸세요. |
| 출력 파일 또는 보고서가 이미 있음 | 다른 출력 파일명을 지정하세요. |
| HWPX 또는 보호된 파일 오류 | 지원하지 않는 입력입니다. 확장자만 바꿔서는 변환되지 않습니다. 작성자에게 보호 설정이 없는 HWP 5 또는 DOCX 사본을 요청하세요. |
| 파일 읽기 또는 검증 실패 | 지원하지 않는 내용이나 손상된 데이터가 있을 수 있습니다. 원본을 보관하고, 사용 가능한 DOCX가 생성되었다고 가정하지 마세요. `--recover-text`는 인코딩 관련 오류에만 사용하세요. |
| WMF 이미지 오류 | WMF 삽입은 지원하지 않습니다. 원본 문서를 작성한 프로그램에서 DOCX로 내보내세요. |
| `Runtime setup is locked` | 다른 설치가 끝날 때까지 기다리세요. 실행 중인 설치가 없음을 확인한 경우에만 오류에 표시된 잠금 폴더를 제거하세요. |
| 원본과 배치가 다름 | 설치된 글꼴을 확인하고, 1단 문서는 페이지 유지 옵션을 시도하거나 Word에서 직접 조정하세요. 완전히 동일한 레이아웃은 지원하지 않습니다. |

전체 명령어 도움말:

```sh
npx hwp-to-word --help
```

## 지원 범위

### HWP 3 (실험적 지원)

- 파일 식별 정보로 HWP 3.x를 구분하며, 비압축 파일과 gzip/raw DEFLATE 압축을 처리합니다.
- ASCII·현대 한글 음절, 기본 글자 서식, 탭·공백, 문단 간격, 용지 크기·여백과
  문단에 명시된 페이지 나누기를 변환합니다.
- 직사각형 표, 일반 셀 병합, 중첩 표와 기본 셀 테두리를 지원합니다.
  텍스트 상자는 편집 가능한 본문 텍스트로 바뀝니다.
- 기존 한자·특수문자·옛한글 코드, 그림, 수식, 필드, 머리말·꼬리말, 각주,
  캡션, 대각선 셀과 단·구역 나누기는 오류로 처리합니다.
- 문단 정렬은 왼쪽 정렬로 바꾸고 경고합니다. 셀 음영, 문단·쪽 테두리,
  글자 그림자·외곽선, 메타데이터와 정확한 배치는 유지하지 않습니다.
  저장된 줄 경계로 페이지를 재구성하지 않습니다.

**실제 HWP 3 문서와의 호환성은 아직 검증하지 않았습니다.** 한컴 규격의 구조를 바탕으로
만든 파일로 압축·본문·표·오류 처리를 테스트했습니다. 공개 규격은 전체 내부 문자표와
DOS 정렬 순서에 대해 별도 설명서를 참조합니다. 실제 HWP 3 파일을 통한 호환성과
시각적 검증이 필요하며, 자체 생성 테스트만으로 이를 보장할 수 없습니다.

### HWP 5

편집 가능한 텍스트와 표, 기본 글자 서식, 셀 병합, 표 테두리와 배경색, 여러 구역 및
구역별 페이지 크기·방향·여백을 지원합니다. 이미지 지원은 제한적입니다.

자동 목록, 수식, 벡터 도형, 캡션과 위 하이퍼링크 이외의 필드는 지원하지 않습니다.
텍스트 상자는 편집 가능한 본문 텍스트로 바뀝니다. 머리말·꼬리말과 활성 링크는 위에
설명한 범위에서 지원합니다. 지원하는 이미지는 글자처럼 배치하며,
떠 있는 위치, 자르기, 회전, 효과는 보존하지 않습니다. PDF 미리보기는 생성하지 않습니다.

지원하지 않는 컨트롤과 머리말·꼬리말 구조, 캡션, 묶음 그림, 벡터 전용 도형과
잘못된 문서 구조는 조용히 누락하지 않고 오류로 처리합니다. 한양 글꼴의 옛한글 전용
코드는 유니코드 사용자 정의 영역 문자로 유지하고 경고하며, 글리프 호환성은 보장하지
않습니다. 구현과 테스트 범위는 [파서 구조](PARSER.md)를 참고하세요.

## 개인정보와 로컬 파일

변환기는 컴퓨터에서 실행되며 문서를 업로드하지 않습니다. 환경 설정 중에는 npm 및
Python 패키지를 다운로드합니다. Python 실행 환경은 `~/.cache/hwp-to-word`에 저장하여
재사용하며, `XDG_CACHE_HOME`이 설정되어 있으면 `$XDG_CACHE_HOME/hwp-to-word`를 사용합니다.
다른 캐시 경로를 사용하려면 `HWP_TO_WORD_CACHE`를 지정하세요.

신뢰할 수 있는 문서만 변환하세요. 파서는 샌드박스에서 실행되지 않으며, 파일 크기와
시간 제한만으로 악성 파일을 안전하게 처리할 수는 없습니다.
변환 보고서에도 문서 관련 정보가 포함될 수 있으므로 공유 전에 내용을 확인하세요.
